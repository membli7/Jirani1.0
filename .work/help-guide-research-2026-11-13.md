# Help & Guide research notes

- W3C WAI, [Writing for Web Accessibility](https://www.w3.org/WAI/tips/writing/): use informative titles, meaningful headings, descriptive link text, clear instructions (including input formats), and clear, concise copy.
- W3C, [WCAG 2.1](https://www.w3.org/TR/WCAG21/): headings and labels should describe their purpose (2.4.6); keyboard focus must be visible (2.4.7); link purpose should be understandable (2.4.4/2.4.9); and page structure should support navigation (2.4.1/2.4.5).
- W3C, [Making Content Usable for People with Cognitive and Learning Disabilities](https://www.w3.org/TR/coga-usable/): use short, single-topic chunks, short descriptive headings, lists, and clear step-by-step instructions placed before or beside the task.
- GOV.UK, [Writing for user interfaces](https://www.gov.uk/service-manual/design/writing-for-user-interfaces): keep UI copy short and direct, put important information first, write in the user's terms, use “you/your” for the user, and use “we/us” only when the service identity is clear.

Application: organize the guide around member tasks and role-specific tasks; use short numbered steps, exact verified control names, descriptive in-page links, semantic headings, and the app's existing English/Kiswahili preference. These sources inform the guide's usability, not Chama product behavior.
